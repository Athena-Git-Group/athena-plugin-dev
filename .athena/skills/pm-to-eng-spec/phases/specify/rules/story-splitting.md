# 故事切分 · 優先級 · FR/NFR 歸戶判準

> `specify` phase 產 `spec.md` 節 1（使用者故事）與節 3（全域需求）時的判準。
> 難判時參考；簡單需求（單一角色、少數行為）依比例原則切 1–2 個故事即可，不必硬拆。

## 判準 1 · 故事以「可獨立驗證的使用者價值」切分（MUST）

每個使用者故事必須代表一段可被**單獨理解、單獨驗證、單獨展示**的使用者價值，
而不是把功能清單或技術工作照句子順序拆成幾段。

- 切完的故事要能回答：**作為誰、想完成什麼、因此得到什麼價值**。
- 只有內部實作步驟、資料處理細節或 UI 元件名稱、沒有對應使用者成果的段落，
  不能拿來當故事標題。

✅ 好的切法（三段各自對應獨立的使用者成果）

```md
### 使用者故事 1 — 依日期自動整理照片 (Priority: P1)
### 使用者故事 2 — 在首頁瀏覽日期相簿 (Priority: P2)
```

❌ 壞的切法（把功能句子 / 實作片段直接當故事）

```md
### 使用者故事 1 — 匯入照片
### 使用者故事 2 — 日期欄位解析
### 使用者故事 3 — 拖放元件
```

## 判準 2 · 優先級依商業價值與交付順序（MUST）

- `P1` 是**最先需要被證明的核心價值**，不是「看起來最酷的」。
- 後續故事的價值若建立在前一故事的結果上，優先級往後排；**不可依需求文字出現順序決定**。
- 每個故事都要寫 `**為何為此優先級**`，說清楚排序理由，不能只標 P1 / P2 / P3。

✅ 「這是核心價值；自動分組不成立，後續瀏覽與排序都無法成立。」
❌ 「因為拖放看起來最酷。」

## 判準 3 · 每個故事保留最小必要的驗證資訊（SHOULD）

至少要有：故事敘述、Priority、優先級原因、**獨立驗證方式**、≥ 1 條驗收情境。

- `獨立驗證方式` 描述「只實作這個故事時，如何驗證它成立」。
- 驗收情境先覆蓋主要成功路徑，再視需要補高風險例外；
  **完整的邊界與錯誤情境放 `spec.md` 的「邊界情況」節**，那裡才是 `gherkin` 的邊界素材來源。

## 判準 4 · 能歸屬單一故事的 FR / NFR 直接掛在故事底下（MUST）

- 判斷方式：**這條需求在支撐哪一段使用者價值？** 而不是先把 FR 集中、再把 NFR 集中。
- 某故事目前沒有專屬 NFR 就不硬湊，但**不可**為了整理方便，把明顯屬於該故事的 NFR
  留在全域區。

## 判準 5 · 全域需求只保留跨故事或無法歸戶者（MUST）

- 只有會**同時約束多個故事**、或本質上無法指派給單一故事的 FR / NFR 才放全域需求。
- 一條需求若被多個故事間接使用、但主要仍服務其中一個，歸到那個故事。
- 全域需求是**例外處理，不是預設集散地**——它重新變成 FR / NFR 總表，就等於沒做歸戶。

## 判準 6 · 歸戶後不得重複列在多個位置（SHOULD）

- 同一條 FR / NFR 只出現在**一個**最合適的位置；不得同時複製到故事區與全域需求區。
- 真的需要在他處提及時：故事區保留正式需求陳述，他處只寫敘述性說明，不重複編號條目。
- 需求編號全域唯一，不得同一編號出現兩種敘述。

## 判準 7 · 局部缺口標記，不憑空補完（SHOULD）

- 需求存在已確認、但做法 / 量化門檻 / 適用範圍未拍板，且不阻塞整份規格
  → 用 `[NEEDS CLARIFICATION: …]` 就地標記，或寫進「假設」段。
- **只有**缺口會改變故事切分、需求歸戶、主要流程或成功標準時，才走
  `specs/<slug>/clarify/questions.md` 的缺口升級協議（每輪 ≤ 3 題）。
- 不可為了讓文件看起來完整，就替使用者發明未確認的細節。

## 與下游的對應（切故事時順手確認）

| 下游 phase | 主要吃 `spec.md` 的哪一部分 |
|-----------|---------------------------|
| `data_model` / `db_table` | 關鍵實體 + **資料維度與範例資料** |
| `class_diagram` | 故事專屬 FR / 全域需求 / 邊界情況（行為與規則） |
| `screens` / `ui_contract` | 使用者故事（角色與流程）+ 邊界情況 + 範例資料（fixtures） |
| `api` | FR / 全域需求（資源與行為）+ 邊界情況 |
| `gherkin` | FR + 邊界情況 + **範例資料**（判定值）+ 成功標準（覆蓋對照） |

故事切完後回頭看這張表：**某個下游欄位在 `spec.md` 找不到素材，就是切分或承載沒做完。**
