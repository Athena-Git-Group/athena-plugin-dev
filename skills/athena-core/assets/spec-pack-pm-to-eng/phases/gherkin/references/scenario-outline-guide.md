# Scenario Outline / Examples / Data Table 使用準則

> 配合 `gherkin-guide.md`。本檔回答「同一條規則的多個案例，怎麼收成資料驅動的場景」。

## 1. 何時用 `場景`、何時用 `場景大綱`

| 情況 | 用 |
|---|---|
| 規則只有**一個**有代表性的案例 | `場景`（單一） |
| 同一規則、**同樣的步驟**、只有**輸入 / 期望輸出不同**（多個等價類 / 多個邊界值） | `場景大綱` + `例子` |
| 步驟結構不同（不同的 When / 不同的驗證流程） | 拆成**不同的 `場景`**，不要硬塞進同一個大綱 |

判斷法則：**步驟文字一字不改、只有值在變 → 用 `場景大綱`**。否則拆開。

---

## 2. `場景大綱` + `例子` 基本形

用 `<佔位符>` 參數化，`例子` 表每一列是一個**具體案例**（Spec by Example）：

```gherkin
場景大綱: 依退款金額判定退款結果
  假設 訂單 ORD-001 的金額為 1000 元、狀態為「已付款」
  當 我對訂單 ORD-001 申請退款 <申請金額> 元
  那麼 退款結果應為 <結果>
  而且 回應碼應為 <回應碼>

  例子:
    | 申請金額 | 結果   | 回應碼 |
    | 1000     | 成功   | 200    |
    | 1        | 成功   | 200    |
    | 1001     | 拒絕   | 422    |
    | 0        | 拒絕   | 400    |
```

- **欄名 = 佔位符名**（中文可，但要與步驟內 `<...>` 完全一致）。
- 每一列都是真實具體值，來源與嚴格度依 `gherkin-guide.md` §4（判定值溯源、缺則回報）。

---

## 3. 一個 Examples 表 = 一個等價類群；邊界值各佔一列

設計 `例子` 列時，**對每個輸入維度涵蓋等價類 + 邊界值**（QA 思想，配合 `boundary-checklist.md`）：

以「退款金額」對「訂單金額上限 1000」為例：

| 列 | 值 | 為什麼選它 |
|---|---|---|
| 下界內 | `1` | 最小有效值 |
| 上界 | `1000` | 邊界值 max |
| 上界 +1 | `1001` | 邊界值 max+1（最易出錯） |
| 非法 | `0` / `-1` | 等價類：非正數 |

> 一條規則涉及多個獨立維度時，**不要**做笛卡兒全展開（組合爆炸）。每個維度各自一組邊界列、其他維度固定在代表值即可。需要交互覆蓋時才針對性加列，並在註解寫明測的是哪個交互。

## 4. 邊界 / 錯誤列排在前面 + 標籤分群

呼應 `gherkin-guide.md` §5（邊界優先）。可用 `例子` 分表 + 標籤，讓下游選擇性執行：

```gherkin
場景大綱: 依退款金額判定退款結果
  假設 訂單 ORD-001 的金額為 1000 元、狀態為「已付款」
  當 我對訂單 ORD-001 申請退款 <申請金額> 元
  那麼 退款結果應為 <結果>
  而且 回應碼應為 <回應碼>

  @error
  例子: 非法輸入（先暴露）
    | 申請金額 | 結果 | 回應碼 |
    | 0        | 拒絕 | 400    |
    | -1       | 拒絕 | 400    |

  @boundary
  例子: 邊界值
    | 申請金額 | 結果 | 回應碼 |
    | 1000     | 成功 | 200    |
    | 1001     | 拒絕 | 422    |

  @happy
  例子: 正常案例
    | 申請金額 | 結果 | 回應碼 |
    | 500      | 成功 | 200    |
```

## 5. Data Table（步驟內表格）

`場景大綱`/`例子` 是**橫向參數化**；步驟內 Data Table 是**承載結構化輸入或多筆驗證**，兩者用途不同。

**用途 A — 一筆結構化輸入**（欄位多時比一長串文字清楚）：

```gherkin
場景: 以多欄位建立訂單
  當 我建立訂單，內容為：
    | 欄位     | 值       |
    | 客戶     | 王小明   |
    | 金額     | 1000     |
    | 幣別     | TWD      |
  那麼 訂單應建立成功（HTTP 201）
```

**用途 B — 驗證多筆結果**（列表斷言）：

```gherkin
場景: 查詢某客戶的所有訂單
  假設 客戶「王小明」有以下訂單：
    | 訂單編號 | 金額 | 狀態   |
    | ORD-001  | 1000 | 已付款 |
    | ORD-002  | 500  | 待付款 |
  當 我查詢客戶「王小明」的訂單
  那麼 應回傳 2 筆訂單
  而且 訂單編號應包含 ORD-001 與 ORD-002
```

選用法則：
- 值在變、步驟不變、要跑很多列 → `場景大綱` + `例子`。
- 一次帶入 / 驗證一組結構化資料 → 步驟內 Data Table。
- 兩者可並用（大綱的某一步用 Data Table），但別讓單一場景過載——超過約 7 欄就回頭想是不是該拆規則。

## 6. ✅ / ❌

- ✅ 步驟文字固定、只有 `<值>` 在變 → 場景大綱。
- ✅ 每列具體值、邊界列在前、用 `@boundary`/`@error`/`@happy` 分群。
- ❌ 把「不同步驟結構」硬塞同一個大綱（該拆 `場景`）。
- ❌ 笛卡兒全展開把 `例子` 表撐到數十列（組合爆炸，改逐維度邊界）。
- ❌ `例子` 出現抽象值（`合理金額`）或自編的判定值（違反溯源，見 `gherkin-guide.md` §4）。
