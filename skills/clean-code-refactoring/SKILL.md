# Clean Code 重構規範

依使用者的 coding 規範撰寫、審查或重構程式碼：先掃描異味，再對應手法編號，最後在測試保護下小步重構。

# SOP

## Phase 1 -- 收斂任務模式與範圍

1. READ 讀取使用者需求與目標程式碼，判斷本次是「撰寫新程式碼」「審查（只報告）」或「重構（實際改碼）」，並收斂要處理的檔案範圍、語言與版本（無法取得時記下假設），以及專案的編譯、測試、Linter、格式化指令。
2. WRITE 若為撰寫模式，先讀取 `rules/設計原則.md`，再依已載入規則完成程式碼初稿，作為後續掃描對象。

## Phase 2 -- 掃描程式碼異味

1. READ 讀取 `rules/程式碼異味掃描判準.md`。
2. THINK 依已載入規則逐項掃描目標程式碼，列出命中的異味編號、`檔案:行號`、嚴重度與建議搭配的手法編號；審查或重構模式未命中任何異味時直接結束並回報，撰寫模式未命中時直接進入 Phase 4。

## Phase 3 -- 對應重構手法並產出結論

1. READ 依 Phase 2 列出的手法編號按需讀取尚未載入的規則檔：26–50 讀取 `rules/函式與類別整理手法.md`；51–75 讀取 `rules/條件分支與迴圈整理手法.md`；79–83、91–95、97、100 讀取 `rules/設計原則.md`；其餘 76–99 讀取 `rules/安全重構流程.md`。
2. THINK 依已載入規則為每個異味選定手法編號，排除目標語言或版本不支援的手法，並確認每個手法都不改變外部行為。
3. WRITE 若為審查模式，讀取尚未載入的 `rules/安全重構流程.md`，以及 `templates/重構審查報告.md` 與 `templates/重構審查報告.example.md`，依骨架產出報告後停止，不修改程式碼。

## Phase 4 -- 小步重構並驗證行為不變

1. READ 若尚未載入，讀取 `rules/安全重構流程.md`。
2. THINK 依已載入規則排定重構前的測試保護、修改順序與重構後的收尾項目；撰寫模式沒有既有行為可鎖定，測試保護改為替新程式碼補單元測試。
3. WRITE 依已載入規則與 Phase 3 結論逐一套用手法；每套用一個手法就先完成下一步的驗證，通過後才回到本步套用下一個。
4. DELEGATE 執行 Phase 1 收斂出的編譯與測試指令驗證剛套用的手法；全部手法完成後，再執行 Linter 與格式化指令。
5. READ 回頭檢查結果是否符合已載入規則與 Phase 3 結論；若不符合，立即修正。
